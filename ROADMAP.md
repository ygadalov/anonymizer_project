# План доработок Redact: v6.4–v7.0

Согласован 1 ноября 2026 года, дополнен 2 ноября после проверки финансовой модели.
Базовая версия — v6.3 из ветки
`codex/redact-v6.3-sheetjs`.

Этот файл фиксирует план, а не выполненные изменения. Версия приложения пока
остаётся 6.3. Каждый законченный выпуск повышает версию на 0.1:
v6.4 → v6.5 → v6.6 → v6.7 → v6.8 → v6.9 → v7.0.
Обезличивание PPTX и PDF отложено до исправления недостатков текущей версии.
Нумерация этапов пересмотрена: работа с формулами и настройками свободных листов
идёт перед Word. Все ранее согласованные задачи сохранены; восстановление типов
включено в v6.4, удаление фраз и повторений объединено в v6.9.

## 1. v6.4 — сохранность данных CSV и восстановление типов

- [ ] Сохранять длинные числовые коды текстом, исключить округление при импорте.
- [ ] Проверить ведущие нули, счета, разделители и десятичные значения.
- [ ] Добавить регрессионный пример: `123456789012345678` не должен превращаться
  в `123456789012345680`.
- [ ] Исправить превращение логических значений в строки при восстановлении.
- [ ] Проверить числа, даты, текстовые коды и пустые ячейки.
- [ ] Сохранить совместимость со старыми ключами.

Готовность: импорт и экспорт без преобразований сохраняют исходные значения;
длинные коды точно восстанавливаются по ключу. Обратимые методы возвращают
исходные значения и типы; старые ключи продолжают открываться.

## 2. v6.5 — надёжная загрузка файлов и режимы листов

- [ ] Заменять текущие данные только после успешного чтения нового файла.
- [ ] Блокировать экспорт во время загрузки.
- [ ] Исключить смешивание результатов параллельных загрузок.
- [ ] Применить правила к Excel/CSV, Word и восстановлению.
- [ ] Проверить сценарий: корректный CSV → неподдерживаемый DOCX во вкладке
  Excel. Старый CSV не должен скачиваться под именем неудачно загруженного файла.
- [ ] Подписать переключатель «Режим текущего листа»: сейчас режим задаётся
  каждому листу отдельно, новый лист по умолчанию открывается как таблица.
- [ ] Добавить действие «Применить режим ко всем листам».
- [ ] Добавить обзор книги: лист, выбранный режим, количество формул
  и запланированных изменений.
- [ ] Проверить сохранение режима при переходах между листами и загрузке настроек.

Самопроизвольный сброс режима в проверенной модели не воспроизведён:
после настройки восьми листов как свободных режим сохранился при 16 переключениях.
Не описывать это как подтверждённую ошибку переключения.

Готовность: после ошибки остаётся прежний документ с прежним именем либо явно
пустое состояние. Данные разных файлов не смешиваются; режим каждого листа
понятен пользователю и сохраняется при возврате на него.

## 3. v6.6 — формулы, сохранённые результаты и безопасный экспорт

- [ ] Показывать признак формулы ƒx отдельно от типа её результата
  (число, текст, дата и т. д.).
- [ ] Явно разделить два сценария: «Сохранить расчётную модель»
  и «Передать обезличенные значения».
- [ ] При сохранении модели менять только выбранные исходные ячейки,
  сохранять формулы, очищать исходные кэшированные результаты и запрашивать
  пересчёт при открытии. Проверять отсутствие кэша в самом экспортированном XLSX.
- [ ] При экспорте значений использовать сохранённые результаты формул,
  применять выбранные преобразования и удалять формулы. Не считать этот сценарий
  сохранением работоспособной расчётной модели.
- [ ] Показывать статусы: формула сохранится; исходный результат будет очищен,
  нужен пересчёт; формула заменится обезличенным значением; результата нет
  или он содержит ошибку. Отсутствие результата не подменять нулём.
- [ ] Разделить счётчики: изменённые исходные ячейки, сохранённые формулы,
  преобразованные результаты и оставленные без изменения ячейки.
- [ ] Учесть текст, литералы и ссылки внутри формул: сохранение формулы
  и очистка кэша сами по себе не гарантируют удаления чувствительных данных.
- [ ] Проверить числовые, текстовые, логические результаты, даты, нули,
  ошибки, общие формулы и ссылки между листами.

Готовность: исходные результаты формул не остаются в обычном экспорте скрыто;
в экспорте значений формулы отсутствуют, а выбранные результаты преобразованы.
Интерфейс не выдаёт сохранение формул за обезличивание всех расчётных данных.
Проверка сохранности формул отдельно от проверки корректности их пересчёта.

## 4. v6.7 — точные настройки свободного листа и финансовых моделей

- [ ] Добавить настройку по ячейкам и диапазонам: лист, адрес, подпись показателя,
  тип, формула/значение, действие и предпросмотр результата.
- [ ] Действия: оставить, умножить на общий коэффициент, заменить текст или код,
  сдвинуть дату, очистить. Для формул согласовать действие со сценарием v6.6.
- [ ] Разделить роли: деньги, процент, количество, год, код. Не определять
  денежную сумму исключительно по величине числа; учитывать единицы измерения.
- [ ] Сохранить существующие исключения найденных текстовых значений и типов;
  добавить исключения отдельных чисел, дат и диапазонов.
- [ ] Явно обозначить область действия настроек: текущая ячейка, диапазон,
  лист или все свободные листы. Сейчас переключатели чисел/дат общие.
- [ ] Предупреждать о частичном масштабировании денежных исходных данных;
  не обещать сохранение финансового смысла модели при произвольной смене драйверов.
- [ ] Сохранять и восстанавливать настройки свободных листов: роли и действия,
  диапазоны, исключения значений/типов, пользовательские замены, переключатели
  чисел/дат. Сохранять совместимость с прежними файлами настроек.
- [ ] Проверить повторяющиеся значения с разными действиями в разных ячейках,
  согласованность словаря замен и точность восстановления по ключу.

Готовность: небольшую целую сумму в миллионах можно масштабировать явно,
процент или количество — оставить; настройки воспроизводятся после сохранения
и загрузки. Масштабирование не распространяется на исключённые ячейки.

## 5. v6.8 — полнота предпросмотра Word

- [ ] Показывать количество отображённых элементов и предупреждение о лимите.
- [ ] Добавить порциональную загрузку остального текста.
- [ ] Сделать понятным состояние фильтра «Только с заменами».

В v6.3 предпросмотр ограничен 3000 элементами, а не числом символов. Элементом
может быть абзац, строка таблицы либо текст из колонтитула, сноски или примечания.
Высота области — 560 px с прокруткой. Фильтр может скрывать неизменённый текст.

Готовность: пользователь может просмотреть весь поддерживаемый текст документа
и понимает, какая часть сейчас скрыта.

## 6. v6.9 — удаление фраз в Word и управление повторениями

- [ ] Выделение текста в предпросмотре → «Удалить выделенное».
- [ ] По умолчанию удалять только выбранное вхождение.
- [ ] Поддержать абзацы, ячейки таблиц и фразы с разным оформлением.
- [ ] Добавить отмену удаления до экспорта и отображение запланированного удаления.
- [ ] Физически удалять текст из DOCX, включая его следы в записанных исправлениях;
  не ограничиваться визуальным скрытием.
- [ ] Предупреждать: по ключу удалённая фраза не восстанавливается.

- [ ] Команда «Удалить все точные совпадения» с количеством и списком вхождений.
- [ ] Возможность вернуть отдельное удаление.
- [ ] Согласовать удаления фраз с удалением абзацев и разделов.
- [ ] Проверить пересекающиеся диапазоны и повторы в разных частях документа.

Готовность: по умолчанию удаляется только выбранное вхождение; остальной текст
и оформление сохраняются. В экспортированном DOCX удалённого текста нет.
Повторения удаляются только по явному выбору. Пересекающиеся удаления работают
предсказуемо; интерфейс предупреждает, что ключ их не восстановит.

## Правила выпуска каждой версии

1. Реализовать доработку и проверки изменённого поведения.
2. Прогнать существующие тесты и затронутые браузерные сценарии.
3. Проверить обезличивание → экспорт → восстановление, где оно предусмотрено.
4. Повысить версию на 0.1, обновить CHANGELOG и собрать автономный HTML.
5. Отметить выполненные пункты этого плана.

Исходная проверка v6.3: 29 модульных тестов прошли; браузерный офлайн-сценарий
CSV/XLS с восстановлением прошёл; сборка совпала с готовым HTML побайтово.
Это результаты базовой версии, а не подтверждение готовности будущих выпусков.

Дополнительная проверка v6.3 на финансовой модели (2 ноября 2026 года):

- 8 листов, 438 формул с сохранёнными результатами и 1 диаграмма.
- При настройке всех листов как свободных обычный экспорт изменил 14 ячеек,
  включая 11 числовых констант из 102. Пороговая эвристика не подходит для
  автоматического выбора всех денежных показателей финансовой модели.
- Все 438 формул и их исходные кэшированные результаты остались в обычном
  экспорте; это основание для задачи v6.6.
- Восстановление вернуло значения обычных ячеек и тексты формул всех листов;
  диаграмма при экспорте потеряна и ключом не восстанавливается.
- Экспорт для внешней передачи оставил 8 листов, удалил формулы и условное
  форматирование. Это не подтверждение обезличивания всех денежных результатов:
  выбор преобразований требует доработки v6.7.
- Ошибок JavaScript не было. Пересчёт в Excel не выполнялся; корректность
  финансовых расчётов после изменения исходных данных не подтверждена.

Проверки расширять синтетическими финансовыми моделями. Не коммитить
пользовательскую книгу, выгрузки, ключи или её финансовые значения в репозиторий.

## После стабилизации — отдельно от текущего цикла

Сначала оценить и реализовать PPTX, затем PDF. Перед расширением выделить общий
поиск чувствительных данных, словарь замен и отчёт проверки из модулей форматов
без полной переписи приложения.

- PPTX: учитывать текст, таблицы, заметки, скрытые слайды, образцы и макеты,
  диаграммы, вложения и изображения. Неподдерживаемое содержимое явно отмечать.
- PDF: выделение фразы должно приводить к реальному удалению содержимого,
  а не перекрытию прямоугольником. Для сканов понадобятся OCR и ручное выделение
  областей. Способ экспорта и ограничения восстановления согласовать отдельно.

Версии и сроки этих крупных доработок пока не назначены.
