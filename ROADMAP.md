# План доработок Redact: v6.4–v7.0

Согласован 1 ноября 2026 года. Базовая версия — v6.3 из ветки
`codex/redact-v6.3-sheetjs`.

Этот файл фиксирует план, а не выполненные изменения. Версия приложения пока
остаётся 6.3. Каждый законченный выпуск повышает версию на 0.1:
v6.4 → v6.5 → v6.6 → v6.7 → v6.8 → v6.9 → v7.0.
Обезличивание PPTX и PDF отложено до исправления недостатков текущей версии.

## 1. v6.4 — сохранность данных CSV

- [ ] Сохранять длинные числовые коды текстом, исключить округление при импорте.
- [ ] Проверить ведущие нули, счета, разделители и десятичные значения.
- [ ] Добавить регрессионный пример: `123456789012345678` не должен превращаться
  в `123456789012345680`.

Готовность: импорт и экспорт без преобразований сохраняют исходные значения;
длинные коды точно восстанавливаются по ключу.

## 2. v6.5 — надёжная загрузка файлов

- [ ] Заменять текущие данные только после успешного чтения нового файла.
- [ ] Блокировать экспорт во время загрузки.
- [ ] Исключить смешивание результатов параллельных загрузок.
- [ ] Применить правила к Excel/CSV, Word и восстановлению.
- [ ] Проверить сценарий: корректный CSV → неподдерживаемый DOCX во вкладке
  Excel. Старый CSV не должен скачиваться под именем неудачно загруженного файла.

Готовность: после ошибки остаётся прежний документ с прежним именем либо явно
пустое состояние. Данные разных файлов не смешиваются.

## 3. v6.6 — точное восстановление типов

- [ ] Исправить превращение логических значений в строки при восстановлении.
- [ ] Проверить числа, даты, текстовые коды и пустые ячейки.
- [ ] Сохранить совместимость со старыми ключами.

Готовность: обратимые методы возвращают исходные значения и типы;
старые ключи продолжают открываться.

## 4. v6.7 — полнота предпросмотра Word

- [ ] Показывать количество отображённых элементов и предупреждение о лимите.
- [ ] Добавить порциональную загрузку остального текста.
- [ ] Сделать понятным состояние фильтра «Только с заменами».

В v6.3 предпросмотр ограничен 3000 элементами, а не числом символов. Элементом
может быть абзац, строка таблицы либо текст из колонтитула, сноски или примечания.
Высота области — 560 px с прокруткой. Фильтр может скрывать неизменённый текст.

Готовность: пользователь может просмотреть весь поддерживаемый текст документа
и понимает, какая часть сейчас скрыта.

## 5. v6.8 — удаление отдельной фразы в Word

- [ ] Выделение текста в предпросмотре → «Удалить выделенное».
- [ ] По умолчанию удалять только выбранное вхождение.
- [ ] Поддержать абзацы, ячейки таблиц и фразы с разным оформлением.
- [ ] Добавить отмену удаления до экспорта и отображение запланированного удаления.
- [ ] Физически удалять текст из DOCX, включая его следы в записанных исправлениях;
  не ограничиваться визуальным скрытием.
- [ ] Предупреждать: по ключу удалённая фраза не восстанавливается.

Готовность: удаляется только выбранное вхождение; остальной текст и оформление
сохраняются. В экспортированном DOCX удалённого текста нет.

## 6. v6.9 — повторения и управление удалениями

- [ ] Команда «Удалить все точные совпадения» с количеством и списком вхождений.
- [ ] Возможность вернуть отдельное удаление.
- [ ] Согласовать удаления фраз с удалением абзацев и разделов.
- [ ] Проверить пересекающиеся диапазоны и повторы в разных частях документа.

Готовность: повторения удаляются только по явному выбору. Пересекающиеся удаления
работают предсказуемо; интерфейс предупреждает, что ключ их не восстановит.

## 7. v7.0 — проверка результата и стабилизация

- [ ] Единый отчёт: что обработано, удалено и осталось непроверенным.
- [ ] Уточнить предупреждения о картинках, вложениях, названиях листов
  и дополнительных данных, особенно для внешней передачи.
- [ ] Проверять результат на оставшиеся известные исходные значения.
- [ ] Закрыть подтверждённые дефекты этого цикла, актуализировать ограничения.
- [ ] Выполнить полный набор модульных и браузерных проверок.

Готовность: подтверждённые дефекты цикла закрыты, ограничения явно описаны,
полный набор проверок проходит. Проверка известных значений не является
гарантией обнаружения всех чувствительных данных.

## Правила выпуска каждой версии

1. Реализовать доработку и проверки изменённого поведения.
2. Прогнать существующие тесты и затронутые браузерные сценарии.
3. Проверить обезличивание → экспорт → восстановление, где оно предусмотрено.
4. Повысить версию на 0.1, обновить CHANGELOG и собрать автономный HTML.
5. Отметить выполненные пункты этого плана.

Исходная проверка v6.3: 29 модульных тестов прошли; браузерный офлайн-сценарий
CSV/XLS с восстановлением прошёл; сборка совпала с готовым HTML побайтово.
Это результаты базовой версии, а не подтверждение готовности будущих выпусков.

## После стабилизации — отдельно от текущего цикла

Сначала оценить и реализовать PPTX, затем PDF. Перед расширением выделить общий
поиск чувствительных данных, словарь замен и отчёт проверки из модулей форматов
без полной переписи приложения.

- PPTX: учитывать текст, таблицы, заметки, скрытые слайды, образцы и макеты,
  диаграммы, вложения и изображения. Неподдерживаемое содержимое явно отмечать.
- PDF: выделение фразы должно приводить к реальному удалению содержимого,
  а не перекрытию прямоугольником. Для сканов понадобятся OCR и ручное выделение
  областей. Способ экспорта и ограничения восстановления согласовать отдельно.

Версии и сроки этих крупных доработок пока не назначены.
